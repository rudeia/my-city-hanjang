# 도시 한 장

도시짓기 수업 전에 새 도시를 계획하는 학생용 앱입니다. 빈 도시 선언문에서 시작해 시설을 배치하고 이유와 근거를 쓰면, 같은 내용이 보고서와 브랜드 보드로 모입니다.

- 배포 예정 주소: https://rudeia.github.io/my-city-hanjang/
- 생성 예정 저장소: https://github.com/rudeia/my-city-hanjang

현재 로컬 구현과 검증을 마쳤습니다. 공개 저장소 생성과 Pages 배포는 소스 공개 범위 확인 후 진행합니다.

## 수업에서 쓰기

1. 모델 도시를 고르고 선택 이유, 자료에서 찾은 특징, 내 도시에서 다르게 만들 점을 적습니다. 위성사진을 올리고 참고자료 출처를 남길 수 있습니다.
2. 내 도시 이름, 먼저 생각할 주민, 줄이고 싶은 불편, 바라는 생활을 적어 도시 선언을 만듭니다.
3. 설계판의 큰 칸에 주거·생활시설·공원·일자리·대표 공간을 놓습니다. 도로망은 칸 사이와 바깥 통로에 놓습니다. 시설 20칸과 도로 49구간은 별도로 저장합니다.
4. 공간 전략 세 개의 배치와 이유를 쓰고 교과 개념을 연결합니다. 연구 자료를 골랐다면 배운 점과 적용하기 어려운 점도 적습니다.
5. 가치와 부담, 이후 확인할 일, 이름·슬로건·상징의 뜻을 정리합니다.
6. 보고서를 읽고 계획을 고친 뒤 브랜드 보드를 PNG나 SVG로 저장합니다. 모델 도시·참고사진은 학생의 공간 구상도와 구분해 표시합니다.

빈칸을 정답이나 예시로 채워 주지 않습니다. ‘어떻게 쓰면 될까요?’를 열면 가상 도시의 작성 예시와 검토할 점을 볼 수 있습니다. 예시를 읽어도 학생 답변이나 보고서에는 들어가지 않습니다. 작성 상태는 입력 여부이며 평가 점수가 아닙니다.

참고사진은 JPG·PNG·WebP(10MB 이하)를 선택할 수 있습니다. 브라우저 저장을 위해 긴 변 1400px 이하 JPEG로 준비하며, 사진과 출처는 활동 파일에 함께 담습니다. 사진이 있으면 출처를 적은 뒤 보드 이미지를 저장할 수 있습니다. 사진은 서버로 전송하지 않습니다.

## 저장과 파일

GitHub Pages에서 실행하는 정적 앱으로, 서버나 로그인은 없습니다. 내용은 현재 기기·브라우저의 저장 공간에 보관합니다. 다른 브라우저나 기기에서는 자동으로 이어지지 않습니다.

- **지금 저장:** 현재 브라우저에 저장합니다. 평소에는 입력을 잠시 멈추면 자동 저장합니다.
- **활동 파일 저장:** 글, 시설, 도로, 전략 번호, 선택한 근거를 JSON 파일로 내려받습니다. 브라우저에 저장하지 못한 상태에서도 파일로 보관할 수 있습니다.
- **활동 파일 열기:** 파일을 검사하고 바꿀 내용을 확인한 뒤 불러옵니다. 기존 작업을 남기려면 먼저 활동 파일을 저장합니다.
- **PNG·SVG 저장:** 현재 보고서와 같은 계획으로 브랜드 보드를 만듭니다. 긴 글은 잘라 버리지 않고 필요한 만큼 보드 높이를 늘립니다.

브라우저 데이터 삭제, 시크릿 창 종료 등에 대비해 활동 파일을 따로 보관하세요. 작성 내용이나 내려받은 활동 파일은 GitHub 저장소에 올리지 않습니다. 기존 Sites 앱의 서버 기록도 이 저장소에 복사하지 않았습니다.

## 문장과 예시 검토

안내문은 학생이 바로 할 일을 알 수 있도록 고쳤습니다. 교과 개념과 논문의 이름·출처·한계는 유지했습니다.

| 화면        | 검토한 점                                                                                                      |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| 모델 도시   | 실제로 관찰한 특징, 배울 점, 내 도시에서 바꿀 점을 구분하고 자료 출처를 남기도록 했습니다.                     |
| 도시 선언   | ‘행복한 도시’ 같은 말에서 멈추지 않고 누구의 어떤 생활을 바꿀지 쓰도록 질문했습니다.                           |
| 공간 전략   | 시설 이름만 나열하지 않고 위치·연결·선택 이유가 드러나도록 예시를 썼습니다.                                    |
| 연구 자료   | 연구에서 읽은 생각과 학생의 적용안을 구분하고, 계획만으로 효과를 확인했다고 쓰지 않도록 했습니다.              |
| 가치·검토   | 기대하는 변화뿐 아니라 다른 방법, 비용, 불편해질 주민을 살피도록 했습니다.                                     |
| 브랜드      | 이름·색·상징의 뜻을 실제 공간 계획과 연결하도록 했습니다.                                                      |
| 공유·수정   | 실제로 받은 질문과 바꾼 내용을 쓰도록 했습니다. 예시의 가상 의견을 실제 의견으로 기록하지 않도록 안내했습니다. |
| 보고서·보드 | 학생이 쓰지 않은 설명이나 성과를 추가하지 않고, 같은 글과 구상도를 사용합니다.                                 |

연구 자료 설명은 출처를 밝힌 수업용 한국어 요약입니다. 논문 원문 인용이나 특정 배치의 효과를 입증한 결과로 소개하지 않습니다. 교사는 사용하는 교과서 판본과 수업 범위에 맞춰 내용을 확인할 수 있습니다.

## 개발·배포

Node.js 24와 npm을 사용합니다.

```sh
npm ci
npm run dev
npm test
npm run build
```

`main`에 푸시하면 GitHub Actions가 검사·빌드 후 Pages에 배포합니다. 배포 결과물은 `dist/`입니다. 자산 경로는 상대 경로여서 저장소 하위 경로에서도 동작합니다.

브라우저 검증은 별도의 Playwright 런타임을 지정해 실행할 수 있습니다.

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright node tests/browser.mjs
```

검증 범위: 빈 시작, 저장·새로고침, 도로가 시설을 바꾸지 않는지, 보고서와 보드의 일치, PNG/SVG 다운로드, 다른 브라우저로 활동 파일 이동, 잘못된 파일·저장 실패 때 내용 보존, 작은 화면의 가로 넘침. 실제 학생 기기에서의 사용 확인은 별도입니다.
